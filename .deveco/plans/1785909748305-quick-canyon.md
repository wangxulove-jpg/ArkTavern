# Goal

Fix three critical bugs in group chat:
1. **Prefix nesting/accumulation**: AI message content in DB accumulates `[Name]:` prefixes across rounds because `convertHistoryMessages` adds a prefix on top of already-prefixed stored content
2. **Wrong character name**: AI sometimes outputs a different character's name as prefix (e.g., 微信聊天's message starts with `[叶知弦]:`)
3. **Single-strip only**: `stripSpeakerPrefix` only removes one prefix instance, missing nested prefixes like `[叶知弦]: [叶知弦]: text`

# Scope / Non-goals

**In scope:**
- Make `stripSpeakerPrefix` loop to strip ALL `[Name]:` / `Name:` prefixes from content
- Clean DB content before re-adding prefix in `convertHistoryMessages`
- Strengthen character identity in group constraint prompt
- Handle both bracket `[Name]:` and plain `Name:` formats

**Out of scope:**
- Ghost empty messages (separate issue, cosmetic)
- DB migration to clean existing bad data (will naturally resolve as conversations progress)
- Changes to GroupMessageBubble UI (correctly displays senderName + content separately)

# Design

## Fix 1: `stripSpeakerPrefix` — Loop to strip ALL prefix instances

Current behavior: strips ONE prefix, leaves nested ones behind.

New behavior: loop stripping until no more prefixes match.

```typescript
private stripSpeakerPrefix(content: string, speakerName: string | null): string {
  if (content.length === 0) {
    return content;
  }
  let result: string = content;
  const MAX_STRIP_ITERATIONS: number = 10; // safety limit
  for (let i: number = 0; i < MAX_STRIP_ITERATIONS; i++) {
    // 1. Exact speaker name match (bracket + plain)
    if (speakerName !== null && speakerName.length > 0) {
      const escaped: string = speakerName.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
      const exactPattern: string = '^(?:\\[' + escaped + '\\]|' + escaped + ')[：:]\\s*';
      const exactMatch: RegExpMatchArray | null = result.match(exactPattern);
      if (exactMatch !== null) {
        result = result.substring(exactMatch[0].length);
        continue; // try again for nested prefix
      }
    }
    // 2. Generic bracket [any-name]:
    const bracketMatch: RegExpMatchArray | null = result.match(/^\[[^\]]+\][：:]\s*/);
    if (bracketMatch !== null) {
      result = result.substring(bracketMatch[0].length);
      continue; // try again for nested prefix
    }
    // 3. Generic plain name (1-30 chars, no colon/newline inside, followed by colon):
    const plainMatch: RegExpMatchArray | null = result.match(/^[^：:\n]{1,30}[：:]\s*/);
    if (plainMatch !== null) {
      result = result.substring(plainMatch[0].length);
      continue; // try again
    }
    // No prefix found, done
    break;
  }
  return result;
}
```

**Rationale**: The loop handles all nesting levels. The generic plain name match (step 3) catches cases where the AI outputs a WRONG character's name as prefix (e.g., `叶知弦: ...` when the speaker is 微信聊天). The MAX_STRIP_ITERATIONS prevents infinite loops.

**Risk**: The generic plain name pattern `^[^：:\n]{1,30}[：:]\s*` could false-positive on legitimate content starting with a word followed by a colon (e.g., `注意: 这是重点`). However:
- This only triggers after the exact name match and bracket match fail
- The content starts with the AI's output which is unlikely to start with `Word: ` unless it's a name prefix
- The risk is acceptable given the severity of the current bug

## Fix 2: `convertHistoryMessages` — Strip existing prefixes before adding new one

Current: `'[' + name + ']: ' + msg.content` — blindly adds prefix, causing nesting if content already has prefix.

New: First strip any existing prefixes from `msg.content`, then add a single clean prefix.

```typescript
if (msg.role === ChatRole.Assistant) {
  const charId: string = msg.senderCharacterId !== undefined ? msg.senderCharacterId : '';
  const character: Character | null = charId.length > 0 ? (characterMap.get(charId) ?? null) : null;
  const name: string = character !== null ? character.name : '未知角色';
  // 清理内容中残留的旧前缀(防止嵌套叠加)
  const cleanContent: string = this.stripAllPrefixes(msg.content);
  const prefixedContent: string = '[' + name + ']: ' + cleanContent;
  // ...
}
```

Add a private `stripAllPrefixes()` method to GroupPromptAssembler:
```typescript
private stripAllPrefixes(content: string): string {
  let result: string = content;
  for (let i: number = 0; i < 10; i++) {
    // Try bracket prefix [name]:
    let match: RegExpMatchArray | null = result.match(/^\[[^\]]+\][：:]\s*/);
    if (match !== null) {
      result = result.substring(match[0].length);
      continue;
    }
    // Try plain name prefix:
    match = result.match(/^[^：:\n]{1,30}[：:]\s*/);
    if (match !== null) {
      result = result.substring(match[0].length);
      continue;
    }
    break;
  }
  return result;
}
```

**Rationale**: This ensures the prompt history always has a clean single `[Name]: content` format, regardless of what's stored in the DB. The DB content may still have dirty prefixes from older rounds, but the prompt will always be clean.

# Risks And Compatibility

- **Generic plain-name regex false positive**: `^[^：:\n]{1,30}[：:]` could strip legitimate content like `注意: 这是重点`. Mitigated by: only triggers after exact name + bracket match fail; AI outputs rarely start with this pattern; acceptable risk vs current broken state.
- **Existing DB data**: Old messages with nested prefixes won't be cleaned in DB but will be cleaned at prompt-build time by `stripAllPrefixes`. UI display will still show old nested prefixes for existing messages. Consider: also strip prefixes at `mapRuntimeMessageToUiSync` / `mapMessageToUi` level for display (optional enhancement).
- **MAX_STRIP_ITERATIONS = 10**: Should be more than enough for any realistic nesting. Current worst case in DB is 4-level nesting.
