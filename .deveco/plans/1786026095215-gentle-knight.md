# W1A-WORLD-CORE-CONTRACT Plan Summary

## Goal
Design the core data contract for ArkTavern's world mode, audit existing world code for keep/refactor/replace decisions, and produce a phased implementation roadmap — without modifying any production code.

## Scope
- Read-only audit of 71 world-specific files + 47 related files
- Database schema audit of 8 world tables at VERSION 19
- Design 16 target domain models with field-level specifications
- Produce phased build roadmap (W1A through W9)
- Define first build scope (W1A-BUILD) with exact file list

## Non-goals
- No code modifications
- No data migration design
- No runtime implementation
- No provider/network integration

## Current State
- Branch: `move`, HEAD: `8ae234e`
- DATABASE_VERSION: 19
- 8 world tables: worlds, world_locations, world_location_edges, world_character_instances, world_events, world_scenes, world_scene_messages, world_character_memories
- Missing: WorldPlayerProfile, WorldConversationSession, ParticipantSnapshot, WorldSessionSummary, WorldDirectedRelationship, WorldCharacterKnownEvent, WorldCharacterLocationHistory
- 3 working untracked files (CuratorPage, MemoryEvidencePage + ViewModels)
- docs/ is Git-ignored

## Design Decisions
1. WorldPlayerProfile: Independent table with UNIQUE(worldId) — not embedded in World
2. WorldConversationSession: Independent table, one Active per Scene at a time
3. ParticipantSnapshot: JSON in Session record (not separate table) for W1A simplicity
4. Scene ≠ Session: Scene = narrative context, Session = concrete chat instance
5. Existing tables (worlds, world_locations, world_location_edges, world_character_instances, world_scenes) can be KEPT with field additions
6. world_scene_messages needs sessionId + locationId columns added
7. world_events, world_character_memories need significant field expansions — REPLACED in later phases
8. Curator tables deferred to W7

## Key Files for W1A-BUILD

## Verification

## Risks
- V19→V20 migration must be DDL-only (ALTER ADD COLUMN + CREATE TABLE)
- JSON columns for participantSnapshot need careful null handling in ArkTS
- Adding sessionId to world_scene_messages requires backfill strategy (NULL for historical messages)

## Rollback
- Revert V19→V20 migration: delete new tables, remove added columns
- All changes are additive only — rollback is straightforward
