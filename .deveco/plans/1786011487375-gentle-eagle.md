## C. 当前用户入口

- **世界入口**:`ChatSessionRootView`(Tab 2)的空状态按钮 / `worldEntryCard` → `router.pushUrl` 到 `pages/world/WorldHomePage`。
- **导航链**:
  ```
  Index(Tab2: ChatSessionRootView)
    → WorldHomePage(世界列表)
      → WorldEditPage(新建/编辑世界)
      → WorldDetailPage(世界工作台 = 详情 + 地图 + 子管理入口枢纽)
          ├→ WorldLocationEditPage / WorldEdgeManagePage→WorldEdgeEditPage(地图拓扑)
          ├→ WorldCharacterManagePage→WorldCharacterMovePage / WorldCharacterMemoryPage(角色实例)
          ├→ WorldSceneManagePage→WorldSceneDetailPage(场景历史/手动消息)
          └→ WorldSceneChatPage(场景聊天,从地点弹窗"进入场景"进入)
  ```
  路由用 `router.pushUrl`(非 NavPathStack),参数经 `AppStorage.setOrCreate(PENDING_*_KEY)`,刷新经 `@StorageProp` refresh token。
- **当前首屏(进入世界)**:`WorldDetailPage` —— 它同时承担"详情 + 2D 地点图 + 全部子管理入口"。
- **是否空白地图**:否。当前"地图"是 **2D 节点-连线图**(`Polyline` + `WorldLocationNode`),由 `WorldLocationGraphLayout` 确定性布局计算。**无 3D、无空白 3D 地图体验**。
- **是否无角色可进入**:是。创建世界仅需名称;`WorldDetailPage` 在无角色时渲染空状态;`WorldSceneService.startScene` 仅校验世界/地点 Active 与"同地点≤1 个 Active 场景",**不校验角色**,可在空地点启动场景。
- **是否支持添加角色**:是。`WorldCharacterManagePage` 选择已有角色卡 + 初始地点加入世界(`WorldStateService.addCharacterToWorld`)。
- **点击角色图标**:地图上**没有角色图标**,只有地点节点。点地点节点 → 弹出地点人物 sheet(`WorldLocationSceneSheetViewModel`)→ 列出该地点角色 + "进入场景 / 查看场景历史"。角色级操作(移动/记忆)仅在 `WorldCharacterManagePage` 与 `WorldSceneChatPage` 内可达。
- **死路由 / 重复入口 / Debug 页面**:无。12 路由全部被 push 且全部注册;无 `WorldPreview/Debug/Inspector/Pilot` 文件。
- **分层瑕疵**:`WorldEdgeManagePage.ets:32` 在页面层直接 `import { WorldRepository }`,是唯一页面级直连仓储的点(其余页面经 ViewModel)。

**视觉坐标 vs 逻辑位置**:视觉 x/y 临时计算不存储;逻辑位置 = `WorldLocation.id` + `WorldCharacterInstance.currentLocationId`。**旧代码未用自由坐标决定**参与者/可见性/同地点/移动合法性 —— 全部基于 `locationId`:

- 可见性 = `visibility` 枚举 + `recipientCharacterInstanceIds`(`WorldSceneMessage.ets:36-40`)

**保留结论**:**KEEP**(作为 2D 图可视化)。逻辑位置模型正确、与业务解耦、无废弃 API。目标要求的"3D 空白地图 + 角色图标 + 点击入聊"是**在保留逻辑模型基础上的视觉层重建**(见 L 节),而非删除现有 2D 实现。

## F. 数据库和迁移

- **DATABASE_VERSION = 19**(`DatabaseConstants.ets:9`),`DATABASE_NAME = 'arktavern.db'`。
- **世界表(8 张,全部软引用、无 SQL FK、无 ON DELETE CASCADE,级联由 Service 事务编排)**:
  - v15:`worlds`、`world_locations`(UNIQUE `world_id,canonical_key`)、`world_location_edges`(UNIQUE `world_id,from,to`)、`world_character_instances`(UNIQUE `world_id,character_id`)、`world_events`(append-only)
  - v16:`world_scenes`、`world_scene_messages`(UNIQUE `scene_id,sequence_number`;含 visibility/participant/witness/replyTarget JSON 列)
  - v17:`world_character_memories`(按 `character_instance_id` 索引隔离)
- **索引**:每表配套查询索引(详见 models/repos 审计),覆盖 world_id / location / status / scene_sequence / sender_instance / batch / visibility / memory_instance_status 等。
- **外键**:无 SQL FK;关系完整性由 `WorldStateService`/`WorldSceneService`/`WorldCharacterMemoryService` 在单事务内显式编排。
- **删除规则**(已审计,正确):
  - 删 World:`WorldStateService.deleteWorld` 单事务顺序级联 memory→sceneMessage→scene→event→edge→instance→location→world(`:294-315`)。
  - 删角色卡:`CharacterService.remove` 预检 `countByCharacterId`,被任何世界引用即抛 `CharacterReferencedByWorldError` 阻止删除,**防悬空实例**(`CharacterService.ets:232-243`)。
  - 删 Location:预检"地点有角色/有场景"分别抛 `LocationHasCharacters`/`LocationHasScenes` 阻止;通过后删相关边 + 写 `LocationDeleted` 事件 + 删地点(`:509-540`)。
- **历史迁移(必须永久保留)**:`DbHelper` 按 `buildMigrationPath` 顺序从 `currentVersion` 走到 `DATABASE_VERSION`,**任一步缺失即断升级路径**。必须保留的世界步:
  - v14→v15(建 5 表 + 17 索引)
  - v15→v16(建 2 场景表 + 14 索引)
  - v16→v17(建 world_character_memories + 12 索引)
  - (v17→v18、v18→v19 为 GROUP 域,亦须保留以支持群聊升级)
- **数据迁移风险**:所有世界迁移为纯 `CREATE TABLE/INDEX IF NOT EXISTS`,无 ALTER、无回填、无 DROP,**升级安全**。新概念(PlayerProfile/ConversationSession/Summary/Relationship/EventWitness/Curator/MemoryCorrection)将以 **v20+ 新增表/列**方式引入,**绝不降低 DATABASE_VERSION、绝不删除旧迁移**。

## G. 当前聊天 Runtime

- **单角色 / 多角色场景**:统一用 `WorldScene`(绑定单一 `locationId`)。**单/多角色无独立抽象区分**,均经同一 `WorldSceneChatPage` + `WorldSceneChatViewModel`。
- **是否复用单聊 Runtime**:否。世界用 `WorldSceneService` + 独立 `world_scenes/world_scene_messages` 表,不复用 `ChatService`/`chats/messages`。
- **是否复用 GroupChatRuntimeService**:否。`GroupChatRuntimeService` grep 无 `world` 引用;两域完全隔离。
- **是否存在独立 World Runtime**:**否。无 `WorldRuntimeService`/`WorldRuntimeRegistry`/`WorldPromptAssembler` 文件**,仅在注释中列为"后续阶段"(`WorldSceneService.ets:16`、`DatabaseMigration.ets:732`)。
- **AI 集成**:**完全没有**。世界聊天是**纯手工消息板**:页面 → ViewModel → `WorldSceneService.addUserMessage/addCharacterMessage/addNarratorMessage` → 事务内 `insertWithStore`,消息 `status` 硬编码 `Completed`、`generationBatchId=undefined`。**无 ModelService/Provider/Streaming/Prompt 调用**(`services/world`、`viewmodels/world`、`pages/world` grep `ModelService|Provider|stream|generate|PromptBuilder` = 0 命中)。
- **发言角色确定**:纯手工,用户在次级表单选 `charSenderId`;无自动轮次/无 AI 选角。
- **在场角色确定**:基于地点 —— `listActiveInstancesAtLocationInTx` 取 `currentLocationId==scene.locationId && isActive` 的全部实例(`WorldSceneService.ets:327-339,599-613`)。Public 消息参与者=该地点全部 Active 实例;Private=收件人;快照不可变。
- **地点是否决定参与者**:是。
- **消息位置/场景/会话快照**:消息带 `worldId`、`sceneId`、`participantCharacterInstanceIds`(快照)、`witnessCharacterInstanceIds`、`recipientCharacterInstanceIds`、`replyTargetCharacterInstanceIds`;**不带 `locationId`(可由 scene 推导)、不带 `sessionId`(Scene==Session)**。
- **继续旧会话**:**不能续写**。Ended 场景只读,`insertMessageInTx` 对 `status!==Active` 抛 `sceneNotActive`(`:550-552`);"续"只能在该地点新开场景。
- **新建会话**:`startScene` 新建空场景,**不携带旧历史**(无历史带入 bug)。
- **Token 压缩 / 总结**:**无**。世界域不导入 `TokenCounter`/`HistoryTrimmer`;`loadSnapshot` 加载全部消息无窗口;无 swipe/branch/summary。
- **原始消息保留**:**保留**。`endScene` 仅翻状态+置 `endedAt`,不删消息。
- **Stop / Retry / 迟到回调 / Registry**:**均不存在**(仅模型枚举有 `Streaming/Cancelled/Failed` 值但无代码产生)。并发仅 ViewModel 级 `operationId/isSending/isEnding/disposed` 防重入(`WorldSceneChatViewModel.ets:144-149`)。
- **与单聊/群聊并发冲突**:**无**(独立表 + 仅共享只读 `CharacterService.getById`)。

## H. Prompt 和用户身份

- **当前不构建任何 Prompt** → 泄漏/身份问题**当下不成立**,但 schema 已为未来按角色可见性预留字段。
- **玩家身份来源**:**无 WorldPlayerProfile**。用户是隐式 host(`senderType=User`),无具名玩家、无 `{{user}}` 替换。grep `WorldPlayer|playerProfile|{{user}}|userName` 在世界域 = 0 命中。
- **{{user}} 一致性 / 角色误标为玩家**:数据层已防护 —— `participantCharacterInstanceIds` 禁止含字面 `'user'`(`WorldSceneMessage.ets:252-259`);`senderCharacterInstanceId` 对 Character 必填、对 User/Narrator 禁填(`:211-220`)。未来 PromptAssembler 若复用单聊 `Character.userName` 作 `{{user}}`,须明确"世界 user = 玩家还是 host"——**当前是开放设计缺口,非 bug**。
- **未来装配器须遵守的字段**:visibility 三态(Public/Private/Narrator)、per-instance 记忆(无跨实例读 API)、participant/witness 快照、replyTarget 仅限公开用户消息。
- **未来泄漏风险点(尚未实现,预警)**:`WorldEvent` 是 world 级非 location 级 → 装配器若直接全量注入会跨地点泄漏;无 per-character "已知事件"过滤;`World.description` 全局共享(可接受)。

## I. 当前记忆系统

- **所有权**:`WorldCharacterMemory` 属 `characterInstanceId`(非模板/地点/场景/会话);服务头明确禁止"共享记忆 / 角色之间复制记忆"(`WorldCharacterMemoryService.ets:10-14`)。
- **隔离**:按 `worldId + characterInstanceId`(`WorldCharacterMemory.ets:68-70` + 表列 + 索引);实例 ID 全局唯一已隐含世界隔离。
- **来源**:有 `origin`(Manual/SceneMessage)、`sourceSceneId`、`sourceMessageId`(单 id)、`sourceLocationId`、`occurredAt`、`importance`(1-5)。**SceneMessage origin 当前 UI 不创建**(预留)。
- **场景/地点/同场者**:记忆带 `sourceLocationId`(发生地,非当前地);**不带 witnessIds**;不带 sessionId。
- **移动**:记忆绑定实例,**不绑定 location** → 角色移动后记忆**正确跟随**;`sourceLocationId` 记录发生地,**不会**把旧地点完整聊天上下文带入(因无聊天上下文注入逻辑)。当前无丢失风险(无自动写入)。
- **confidence / version / 归档 / 重建**:无 `confidence`、无 `version`、有 Active/Archived 软删;`updateMemory` 原地覆盖(无历史表/无回滚)。
- **自动覆盖 / 总结被强化 / 读他人记忆 / Curator**:均**不存在**(无 AI、无自动写入、无 Curator、无跨实例读 API)。
- **结论**:记忆系统是**正确的、手工的、可追溯的**基础;缺失 confidence/version/witnessIds/sourceMessageIds 数组,需在 v20+ 补列。

## J. 会话和总结

- **WorldScene / ConversationSession / SessionSummary**:`WorldScene` 存在但**兼任 Session**;无 `ConversationSession` 命名类型;**无 SessionSummary**(`WorldScene` 无 summary 字段/表/生成)。
- **继续会话**:不应加载全部旧消息,但当前 `loadSnapshot` **正是加载全部场景消息**(无窗口/无摘要);AI 接入前需先加窗口。
- **新建会话**:正确——新场景空启动,不携带旧历史。
- **当前不会**:删除旧消息省 Token、只存摘要不存原文、把一份总结复制给所有角色、把客观摘要当所有角色主观记忆、无法追踪摘要来源、无法重生成错误摘要(因为**根本没有摘要**)。
- **证据链设计前瞻**:记忆已预留 `origin/sourceSceneId/sourceMessageId/sourceLocationId`,未来自动提取可逐消息追溯。

## K. 世界事件与证据链

- **WorldEvent / WorldEventAudience / CharacterPerception / Witness / KnownEvent**:`WorldEvent` 存在(append-only 生命周期日志);**其余全缺**;witness 仅在 `WorldSceneMessage`(且为手工)。
