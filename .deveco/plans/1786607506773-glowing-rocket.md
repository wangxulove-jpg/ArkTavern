## Goal
在单人聊天页顶部工具栏（`topBar`）新增一个「状态」按钮。点击后展开一个「角色状态卡片」，以键值列表展示角色当前状态（如 服装/地点/金币）。机制：
1. 用户可**手动添加/修改/删除/锁定**状态字段。
2. AI 每次回复末尾输出一段**隐藏 JSON 状态块**（固定标记），客户端解析后从正文剥离，用户不可见。
3. AI **可自行补充新字段**；被用户**锁定的字段不会被删除**。
4. 状态值**每一轮**都随对话更新，并按会话持久化到数据库。

## Scope / Non-goals
**包含：**
- 顶部工具栏「状态」按钮 + 展开式状态卡片（默认收起）。
- 字段管理：添加、删除、重命名、手动改值、锁定/解锁。
- AI 状态块注入指令、JSON 解析与正文剥离、逐轮合并更新。
- 每会话持久化（数据库迁移 v34）。
- 优雅降级：AI 未输出块 / JSON 非法时不影响正常聊天。

**不包含：**
- 群聊 / 世界模式的角色状态（仅单人 `conversationMode=Single`）。
- 状态历史快照 / 时间轴 / 变更动画。
- 流式期间实时剥离状态块（末帧可能出现极短闪现，可接受）。
- 原生 Function Calling 或额外 AI 提取请求。

## Design

### 1. 数据模型 `models/ChatStatusState.ets`
```ts
export interface ChatStatusEntry {
  name: string;       // 字段名
  value: string;      // 当前值（数字也转为字符串）
  fromUser: boolean;  // true=用户手动添加, false=AI 补充
  locked: boolean;    // true=锁定,AI 未输出时也保留
}
export interface ChatStatusState {
  entries: ChatStatusEntry[];  // 有序列表：用户字段在前, AI 补充字段在后
}
```
- 提供 `createEmptyChatStatusState()`、`serializeChatStatusState(state)`、`parseChatStatusState(json)`（空/非法返回空态）。
- 持久化形态：`chats.status_config_json` 存序列化 JSON 字符串。

### 2. 解析器 `parser/ChatStatusBlockParser.ets`
- `extractStatusBlock(content: string): { cleanContent: string; parsedEntries: ChatStatusEntry[] }`
- 标记：`STATUS_OPEN = '<|status|>'`、`STATUS_CLOSE = '<|/status|>'`；正则匹配**最后一个**块。
- 命中后提取 JSON 并 `JSON.parse`（失败仅剥离标记、返回空数组），逐键转 `ChatStatusEntry`（`fromUser=false, locked=false`，数字值 `String()` 化）。
- 剥离块及其前后多余换行，保证正文结尾干净。

### 3. 持久化（每会话）
- `models/Chat.ets`：`Chat` 增 `statusConfigJson: string`；`CreateChatOptions`/`ChatUpdates` 增可选字段；`createChat`/`updateChat` 默认 `''`。
- `repositories/ChatRepository.ets`：读写 `COLUMN_CHAT_STATUS_CONFIG_JSON`（参照 `COLUMN_CHAT_USER_NAME_OVERRIDE`）。
- 数据库迁移 v34：
  - `DatabaseConstants.ets`：`COLUMN_CHAT_STATUS_CONFIG_JSON = 'status_config_json'`；`DATABASE_VERSION = 34`。
  - `DatabaseSchema.ets`：`CREATE_CHATS_TABLE` 追加该列；新增 `ALTER_CHATS_ADD_STATUS_CONFIG_JSON` 与 `V33_TO_V34_DDL_STATEMENTS`（仅 ALTER）；`V34_SCHEMA_STATEMENTS = [...V33_SCHEMA_STATEMENTS]`（不含 ALTER）；`getSchemaStatements` 注册 `version === 34`。
  - `DatabaseMigration.ets`：新增 `createV33ToV34Migration()` + class。
  - `DbHelper.ets`：import 并在迁移列表末尾（L174）追加 `createV33ToV34Migration()`。

### 4. ChatService 集成
- 新增 `private currentStatusState: ChatStatusState = createEmptyChatStatusState();`
- 会话初始化：`doInitializeSession` 加载 `session.chat` 后 `this.currentStatusState = parseChatStatusState(session.chat.statusConfigJson)`。
- 请求构建：`buildRequestMessages` 末尾调用 `injectStatusInstruction(finalMessages)`——仅当 `currentStatusState.entries` 中存在 `fromUser=true` 的字段时注入；复刻 `injectAvatarDialogueStrategy` 的「找最后 system 下标后插入」逻辑，追加一条 system 消息。
- 状态输出指令文本（字段名动态拼接为 `fromUser` 字段名列表）：
  ```
  【角色状态输出规则】
  在回复正文之后，单独输出一行状态块，格式严格如下（正文不要提及状态块）：
  <|status|>
  {"服装":"...","地点":"...","金币":"..."}
  <|/status|>
  - 优先输出以下字段：服装、地点、金币（与角色/剧情不相关时可省略）
  - 值用简短中文短语，根据角色设定与当前对话合理推断
  - 你可以根据剧情补充新字段（如 心情、体力），但总数不超过 8 个
  - 每轮都要重新输出，反映最新进展
  ```
- 完成收尾：`finalizeAssistantTurn` 在 `finalizeAssistant(...)` 前对 `result.content` 调 `extractStatusBlock` 得 `cleanContent` 与 `parsedEntries`；正文用 `cleanContent`；`parsedEntries` 非空时执行 `applyStatusUpdate(parsedEntries)`。
- **合并规则 `applyStatusUpdate(parsed)`**（每轮执行）：
  - 对每个解析项：已存在（同名）→ 更新 `value`（保留 `fromUser`/`locked`）；不存在 → 追加 `{name, value, fromUser:false, locked:false}`。
  - 对既存但 AI 本轮未输出的字段：`locked=true` 保留；`locked=false` 且 `fromUser=true`（用户字段）保留；`locked=false` 且 `fromUser=false`（AI 补充）删除。
- 持久化与回调：合并后 `persistStatusConfig()`（fire-and-forget 写 `chats.status_config_json`），并触发 `onStatusChanged`。
- 暴露：
  - `getChatStatusState(): ChatStatusState`
  - `updateStatusState(next: ChatStatusState): void`（整态写入：校验→持久化→回调；供字段增删改锁复用）
  - `ChatServiceCallbacks` 增可选 `onStatusChanged?: (state: ChatStatusState) => void`。
- `ChatPersistenceService` 新增 `updateChatStatusConfig(chatId, json)` 写路径（走 `ChatRepository`，保持单一写路径）。

### 5. ChatViewModel 集成
- 新增 `statusState: ChatStatusState = createEmptyChatStatusState()`。
- `createCallbacks()` 实现 `onStatusChanged`：`this.statusState = state; this.onStatusUpdate?.(state)`。
- 新增 `onStatusUpdate?: (state) => void` 供 ChatPage 绑定 `@State`。
- 字段操作（均基于当前 `statusState` 构造新对象后调 `chatService.updateStatusState`）：
  - `addStatusField(name)`（`fromUser:true, locked:false`）
  - `removeStatusField(name)`
  - `renameStatusField(oldName, newName)`
  - `setStatusFieldLocked(name, locked)`
  - `setStatusFieldValue(name, value)`
- 会话操作后（selectSession/createNewSession/deleteSession 等）同步 `statusState = chatService.getChatStatusState()`。

### 6. ChatPage UI
- 新增 `@State statusState: ChatStatusState = createEmptyChatStatusState()`、`@State statusPanelVisible: boolean = false`、`@State statusNewFieldDraft: string = ''`。
- 顶部工具栏 `topBar()` 新增「状态」按钮（`.key('chat.status.toggle')`），点击 `statusPanelVisible = !statusPanelVisible`。
- 新增 `statusCard()`：`if (statusPanelVisible)` 渲染在顶部悬浮 `Column` 中 `topBar()` 之后（L1968 后），形式为浮层卡片：
  - 空态：显示「暂无状态字段，点下方添加」提示。
  - 有值：竖排键值列表；每项显示 `名称：值`，用户字段与 AI 补充字段用不同样式区分，锁定字段带锁图标；每项可点「锁定/解锁」「删除」；用户字段/AI 字段均可点值进入编辑。
  - 底部：「添加字段」`TextInput`（`.key('chat.status.newfield')`）+ 确认按钮。
- 生命周期：`aboutToAppear` 建立 `viewModel.onStatusUpdate = (s) => { this.statusState = s; }`；`aboutToDisappear` 解绑。

## Risks And Compatibility
- **模型格式不遵守**：解析失败仅剥离标记、不更新状态、正文正常显示；指令措辞尽量约束格式。
- **流式闪现**：状态块位于末尾，仅完成前最后一帧可能短暂露出标记；可接受。
- **ArkTS 严格性**：`JSON.parse` 结果窄化校验后构造 `ChatStatusEntry[]`；序列化用接口数组，避免 index signature。
- **数据库迁移**：`ALTER TABLE ADD COLUMN` 增量无破坏；新装通过更新 `CREATE_CHATS_TABLE` 保证列存在；迁移事务失败整体回滚。
- **版本升级不可逆**：`DATABASE_VERSION` 33→34 后旧版应用因高版本保护无法打开该库（既有机制）。

## Rollback
- 代码层：回滚 `ChatService/ChatViewModel/ChatPage/Chat 模型/ChatRepository` 与两个新增文件即恢复原状。
- 数据层：v34 仅新增可空列 `status_config_json`，无数据改动；回退后旧代码不引用该列，无需删除数据。版本号已升 34 时，回退应用需重建数据库或接受现有库（版本保护拒绝降级）。
