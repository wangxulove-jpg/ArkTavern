## 3. 调查结论 A:角色记忆包含哪些信息(双记忆系统)

### A1. 手动记忆 `WorldCharacterMemory`(表 `world_character_memories`,W-MEMORY-1A)
用户通过 `WorldCharacterMemoryPage` 手工创建。字段:
- `worldId` + `characterInstanceId`(记忆所有者 = 世界角色实例,不属于角色模板/地点/场景/会话)
- `type`: `episodic`(经历事件)/ `semantic`(事实认知)/ `reflection`(总结判断)
- `origin`: `manual`(当前唯一创建来源)/ `scene_message`(自动提取预留,UI 不创建)
- `status`: `active` / `archived`
- `content`: 正文(≤2000 字符)
- `importance`: 1-5
- 来源软引用:`sourceSceneId` / `sourceMessageId` / `sourceLocationId`(发生地,非当前位置)/ `occurredAt`
- 引用失效时记忆仍保留,UI 降级显示"地点已删除"等

### A2. 自动会话记忆 `WorldCharacterMemoryEntry`(表 `world_character_memory_entries`,W5)
场景结束后由 AI 从"对该角色可见的消息"自动生成。字段:
- `ownerCharacterInstanceId`(所有者,隔离写入)
- `memoryKind`: `episodic_session`(当前唯一类型)
- `sourceSceneId` / `sourceSessionId` / `sourceLocationId`
- `version`(版本号,新版本 Superseded 旧版本)
- `memoryText`(AI 生成的记忆正文,以角色第一人称 "I remember.../I was told..." 表述)
- `sourceMessageIdsJson` / `sourceMessageCount`(逐条溯源)
- `sourceParticipantInstanceIdsJson` / `sourceWitnessInstanceIdsJson`
- `ownerDisplayNameSnapshot` / `playerDisplayNameSnapshot`
- `confidence`(0-1,表示记忆文本与证据的贴合度,非事实概率)
- `promptVersion` / `providerId` / `modelId`
- `supersedesMemoryId`(取代的旧版本)
- 状态:`active` / `superseded` / `rejected`

### A3. 会话摘要 `WorldSessionSummary`(表 `world_session_summaries`,W4)
场景结束后由 AI 从**公开消息**生成客观第三人称摘要:
- 会话摘要 / 重要决定与承诺 / 未解决事项
- `sourceMessageIdsJson` 溯源、`version` 版本化
- 注入方式:跨会话上下文(见 §5),对所有参与者共享注入

### A4. 两套记忆的差异与关系
- 手动记忆:用户直接编辑,来源任意,importance 1-5,不进入 AI 摘要。
- 自动记忆:AI 从可见消息生成,带 confidence/版本/溯源,结束场景后写入。
- **已知缺陷(不在本次范围)**:手动记忆 `WorldCharacterMemory` 从不注入 Prompt(见 §7 漏洞 P1-1)。

## 4. 调查结论 B:记忆如何保证不丢失

| 机制 | 实现位置 | 效果 |
|---|---|---|
| 记忆绑定实例而非地点 | `WorldCharacterMemory.characterInstanceId`;移动只改 `currentLocationId`,实例 ID 不变 | 角色从 A 地移到 B 地,记忆跟随 |
| 软历史引用 | `sourceSceneId/sourceMessageId/sourceLocationId` 引用失效不级联删除,UI 安全降级 | 来源删除记忆仍在 |
| 级联删除范围最小化 | 仅删实例/删世界时同事务级联(`deleteByCharacterInstanceWithStore`/`deleteByWorldWithStore`) | 不误删 |
| 版本化覆盖 | `persistCompletedMemory` 将旧 Active 置 `superseded` 后写入新版本,`supersedesMemoryId` 链 | 重生成不丢历史 |
| 事务原子性 | 所有跨表写用 `DbHelper.runInTransaction`,事务内只用 `*WithStore` 方法 | 部分失败整体回滚 |
| 来源变更防护 | `persistCompletedMemory` 事务内二次读取消息 ID 集对比,不一致抛 `SourceChanged` 拒绝落库 | 防止脏数据写入 |
| 幂等去重 | `getLatestMemoryForSession` 按 promptVersion+sourceMessageIds 判断 `Existing` 直接复用 | 重复触发不重复消耗模型 |

## 5. 调查结论 C:如何记住准确地点

- **消息级**:每条 `WorldSceneMessage` 带 `locationId`(来自 `scene.locationId`)。
- **会话级**:`WorldSessionParticipantSnapshot.locationIdAtStart` 记录参与者进入会话时的位置。
- **摘要级**:`WorldSessionSummaryStoreService.prepareSourceSnapshot` 的 `locationId = scene.locationId`(正确)。
- **自动记忆级**:`WorldCharacterMemoryStoreService.prepareSourceSnapshot` 的 `locationId = owner.currentLocationId`(**错误,本次 FIX-2 修复**)。
- **注入级**:`WorldCrossSessionContextService.computeMemoryRelevanceScore`:同场景 +2、同地点 +1、会话序号累加,按相关性排序截取注入。
- **Prompt 展示**:`WorldScenePromptAssembler.buildWorldContextSegment` 注入 `[地点·名称]+描述+[场景·标题]+[当前会话 #N]`。

## 6. 调查结论 D:退出会话有没有立即保存 / 立即记忆总结 —— **没有,且这是最大漏洞**

### 现状(已核实代码链路)
1. `WorldSceneChatViewModel.endScene()`(`WorldSceneChatViewModel.ets:624-637`)与 `WorldSceneDetailViewModel.endScene()` 只调用 `sceneService.endScene(sceneId)`,仅将 Scene 状态翻为 `Ended` 并写 `SceneEnded` 事件,**不结束 ConversationSession**。
2. `WorldConversationSessionService.endSession()` **在全工程无任何调用点**(grep 确认只有定义,`WorldConversationSessionService.ets:248`)。
3. 后处理管线 `WorldSessionPostProcessingOrchestrator.processEndedSession()` 唯一外部触发是 `WorldDetailPage.aboutToAppear` 里的 `startResumeIncompleteForWorld(worldId)`(`WorldDetailPage.ets:165-166`),它只恢复 `Pending/Running` 的 run。
4. 但 run 只能由 `getOrCreateForEndedSession()` 创建,而该方法要求 `session.status === Ended`(`WorldSessionPostProcessRunStoreService.ets:67` 抛 `session not ended`)。
5. **结论:session 永不 Ended → run 永不创建 → 摘要/记忆/事件/关系生成管线在 UI 流程中是死代码。**
6. 副作用:跨会话上下文 `WorldCrossSessionContextService` 只读取**已 Ended 且 sequenceNumber 更小**的会话的摘要/记忆(`WorldCrossSessionContextService.ets:96-105,197-207`)→ 跨会话注入恒为空 → **角色实际上没有任何长期记忆进入 Prompt**。

## 8. 新功能可行性结论:"点击地点的人 → 1:1 聊天 → 结束自动总结导入记忆"

**结论:高度可行,基础设施已基本齐全,核心缺口就是 P0-1(会话结束触发)。**

现状盘点:
1. **1:1 场景聊天已可用**:`WorldSceneLauncherViewModel`(`WorldSceneLauncherViewModel.ets`)支持从地点选择参与者启动会话,`setPreselectedInstanceId` 可预选单个角色;`WorldSceneChatViewModel.isSingleParticipant()` 已处理单参与者分支;`WorldSceneRuntimeService` 单参与者直接顺序生成。**点击某个人→预选→启动 1:1 会话的技术链路已存在**。
2. **自动记忆管线已完整实现**:`endSession` → `processEndedSession` → summary 生成(`WorldSessionSummaryGenerationService`)→ per-owner episodic 记忆生成(`WorldCharacterMemoryGenerationService` + `WorldCharacterMemoryPromptAssembler`,第一人称、证据限定、confidence)→ `WorldCharacterMemoryEntry` 落库。
3. **记忆注入已实现**:`WorldScenePromptAssembler` → `WorldCrossSessionContextService.prepareContext` 读取该角色 active memory entries,相关性排序后注入 Prompt。
4. **缺失的只是"扳机"**:在结束场景时正确调用 `endSession` + `startEndedSessionProcessing`,并修复 locationId 来源。之后单聊结束 → 自动生成该角色的会话记忆 → 下次会话自动注入,链路完整。

## 9. Design(推荐实现方案)

### 9.1 FIX-1:结束场景/会话时触发后处理管线(修复 P0-1/P0-2)

**目标**:退出场景时原子完成:场景结束 + 会话结束 + 启动记忆管线。

**方案**:
1. `WorldSceneChatViewModel` 注入 `WorldConversationSessionService` 与 `WorldSessionPostProcessingOrchestrator`(AppServices 已有 getter:`getWorldSessionPostProcessingOrchestrator` `AppServices.ets:1645`;确认 `getWorldConversationSessionService()` 存在,不存在则新增静态 getter)。
2. 修改 `WorldSceneChatViewModel.endScene()`:
   - 先 `sessionService.endSession({ worldId, sessionId })`(若 session 状态为 Active);
   - 再 `sceneService.endScene(sceneId)`(保持原行为);
   - 最后 `orchestrator.startEndedSessionProcessing(worldId, sceneId, sessionId)`(fire-and-forget,内部已 catch,不阻塞 UI);
   - 失败分支:endSession 失败回滚提示;scene end 失败提示(与现有一致);orchestrator 触发失败不阻塞(可依赖 WorldDetailPage 的 resumeIncompleteForWorld 兜底)。
3. `WorldSceneDetailViewModel.endScene()` 同样处理(它有 sceneId;若当前 detail 能取到 session 则结束,无 session 仅结束场景)。
4. **保留** `WorldDetailPage.aboutToAppear → startResumeIncompleteForWorld` 作为中断恢复兜底(进程被杀后 run 残留 Pending 时下次进入世界自动恢复)。

**注意**:pipeline 串行执行 summary→memory→event→knownEvent→relationship,1:1 会话约需 1(摘要)+1(记忆)+可选事件/关系 = 2-4 次模型请求。对单聊可接受;不必改并发模型。

### 9.2 FIX-2:修复自动记忆 locationId 来源(修复 P1-2)

**方案**:`WorldCharacterMemoryStoreService.prepareSourceSnapshot`:
- 通过 `session.sceneId` 加载 `WorldScene`(新增 `WorldSceneRepository` 依赖到 StoreService),取 `scene.locationId`;
- `locationId: scene.locationId`(替代 `owner.currentLocationId`);
- `WorldCharacterMemoryPromptAssembler.loadMetadata` 用 snapshot.locationId 查地点,修复后自动正确。
- 摘要服务已是正确实现(`WorldSessionSummaryStoreService` 用 `scene.locationId`),无需改动。

### 9.3 FEAT-3:点击地点人物 → 1:1 聊天 → 结束自动总结导入记忆

**目标交互**:
- 在世界地图(或地点人物 sheet)点击某个角色 → 弹出"与该角色单独聊聊"入口 → 启动仅含该角色的场景会话(1:1)→ 正常聊天 → 点击"结束场景" → 自动结束会话并后台生成该角色会话记忆(§9.1 已实现)→ 下次进入该角色任何会话,记忆自动注入 Prompt(已实现)。

**方案**:
1. **入口改造**(`WorldDetailPage` 地点人物 sheet `WorldLocationSceneSheetViewModel` / `WorldSceneLauncherViewModel`):
   - 在 `WorldSceneLauncherViewModel` 已支持 `setPreselectedInstanceId` 的基础上,在地点 sheet 的角色条目上增加"单独聊聊"操作:设置 preselect 为该角色实例 ID → 打开 launcher(此时默认仅选中该角色)→ 用户直接启动。
   - 或更直接:在地点 sheet 增加"与 TA 单聊"按钮,调用 `launchService.launchSceneSession({ participantCharacterInstanceIds: [instanceId] })`,成功后跳转 `WorldSceneChatPage`(传入 sceneId + sessionId)。
   - UI 文案与交互细节由 build agent 在实现时按现有页面模式补齐(参照 `WorldDetailPage` 现有的 launcher 弹窗)。
2. **结束流程**:复用 §9.1 的 FIX-1(无需额外改动,单聊场景走同一 `endScene` 路径)。
3. **记忆可视化(可选增强)**:`WorldCharacterMemoryPage` 或 `WorldSceneChatPage` 增加自动记忆(Entry)展示区,让用户能看到"本次会话生成的记忆"。可延后到 FIX-1 验证通过后再做,不阻塞主流程。

## 13. Risks And Compatibility

- **模型请求次数**:结束 1:1 会话会触发 2-4 次后台模型请求,若 Provider 未配置则管线标记失败(已有 `NoModelConfiguration` 分支),不阻塞 UI。用户需知悉"结束即总结"会产生额外 token 消耗。
- **后处理为 fire-and-forget**:结束场景后立即返回;若 App 被杀,run 残留 Pending,由 `WorldDetailPage` 的 `resumeIncompleteForWorld` 下次进入时恢复(已有机制)。
- **DB 兼容**:本次不改 schema、不升级 DATABASE_VERSION(修复均在现有表/服务内)。
- **分层约束**:页面不直接调 service;`endScene` 逻辑放在 ViewModel;orchestrator 经 AppServices 注入(与 `WorldDetailPage` 现有用法一致,保持经 ViewModel 调用)。
- **多参与者场景**:FIX-1 同样作用于多角色会话(会为每个参与者生成记忆),需确认多角色结束不阻塞 UI(管线串行,参与者多则耗时更长,但 fire-and-forget)。
- **FEAT-3 入口与既有 launcher 冲突**:同一地点已有 Active 场景/会话时,launcher 会走 continue 分支;实现"单独聊聊"入口时需处理"该地点已有 Active 场景"的情况(提示用户先结束/继续现有会话,与现有一致)。

## 14. Rollback

- **代码**:按提交粒度 revert。FIX-2 是独立小改动,FIX-1 涉及 3-4 个文件,FEAT-3 涉及入口文件,均可独立 revert。
- **数据**:本方案不迁移数据、不降版本、不删表。若回滚后已生成的摘要/记忆仍保留在表内(无害,不影响旧代码编译);如需清除,仅删测试数据。
- **行为**:FIX-1 回滚后恢复"结束场景不触发总结"的旧行为(即 P0 漏洞原样,但不再有新副作用)。
